# Vercel и Neon

Опубликованная версия: [studyhub-db-dt.vercel.app](https://studyhub-db-dt.vercel.app).
StudyHUB использует **Vercel Hobby** для Next.js и **Neon Free** для PostgreSQL.
Имя проекта — `studyhub-db-dt`. Функции Vercel работают в `fra1` (Франкфурт),
в том же регионе, что и Neon.

У тарифов есть ограничения: проверьте условия [Vercel Hobby](https://vercel.com/docs/plans/hobby)
и [Neon Free](https://neon.com/pricing) перед размещением. Для этого учебного
варианта не требуется отдельный сервер Express или платное файловое хранилище.

## 1. Подключение базы

Создайте пустую PostgreSQL-базу в Neon и возьмите pooled-строку подключения
с SSL. Скопируйте `.env.example` в приватный `.env.local` и заполните `DATABASE_URL`.
Строку подключения не добавляйте в Git, README или параметры с `NEXT_PUBLIC_`.

| Переменная           | Значение на Vercel                                        |
| -------------------- | --------------------------------------------------------- |
| `DATABASE_URL`       | Приватная строка подключения Neon; обязательна.           |
| `STUDYHUB_DEMO_MODE` | `true` для подготовленного учебного набора и выбора роли. |
| `STUDYHUB_ORIGIN`    | `https://studyhub-db-dt.vercel.app`, без пути.            |

На Vercel приложение откажется использовать SQLite при отсутствии `DATABASE_URL`.
`STUDYHUB_DATA_DIR` там не нужен. Выбор роли открывает подготовленные учебные аккаунты;
для обычных пользователей используйте отдельную базу и `STUDYHUB_DEMO_MODE=false`.

## 2. Перенос существующих данных

Остановите запись в исходную SQLite-базу и сохраните её резервную копию.
В целевую PostgreSQL-базу не должны успеть попасть аккаунты, сессии или другие записи:
сначала выполните импорт, затем открывайте сайт.

Из папки проекта, с Node.js 24.x и настроенным `.env.local`:

```powershell
npm ci
npm run db:import -- --source "C:\путь\к\auth.sqlite"
```

`--source` принимает абсолютный путь к существующему файлу SQLite. Команда
проверяет целостность базы, создаёт схему PostgreSQL и переносит записи в транзакции.
Исходный файл открывается только для чтения. После переноса сравниваются количества
записей и контрольные суммы содержимого таблиц.

Сохраняются идентификаторы, пользователи, связи, расписание, задания, оценки,
посещаемость, материалы и объявления. Хеши паролей **scrypt** переносятся без замены:
прежние пароли продолжают действовать. Двоичные файлы из SQLite `BLOB`
сохраняются в PostgreSQL `bytea`.

Сессии и временные ограничения входа (`auth_sessions`, `auth_limits`) не переносятся.
После перехода нужно войти заново. Повторный запуск допускается только для того же
снимка при неизменённых данных назначения; другой снимок или непустая база без
точного маркера отклоняются. Это однократный перенос, а не синхронизация.

Команды `demo:setup` и `demo:seed` готовят только локальную SQLite-базу.
Не запускайте их для заполнения Neon: `demo:seed` отклоняет непустой `DATABASE_URL`.

## 3. Публикация через Vercel CLI

Проект настроен на Next.js, корень репозитория, Node.js 24.x и сборку
`npm run build`. В окружении **Production** должны быть три переменные из таблицы.
Регион функций указан в `vercel.json`.

Из корня локальной копии проекта:

```bash
npx vercel login
npx vercel link --project studyhub-db-dt
npx vercel deploy --prod
```

При привязке выберите аккаунт или команду, где находится существующий проект.
Вход и привязка нужны при настройке нового компьютера; для следующих обновлений
достаточно команды публикации. Она отправляет текущие локальные исходники на Vercel.
Подробности команд: [link](https://vercel.com/docs/cli/link) и
[deploy](https://vercel.com/docs/cli/deploy).

Автоматическая публикация из GitHub пока не подключена: для привязки репозитория
Vercel требует добавить **GitHub Login Connection** в настройках аккаунта.
После подключения можно настроить публикацию при push; текущий способ — CLI.

Случайный preview-адрес не считается разрешённым Origin. Для отдельного preview
задайте его точный Origin и отдельную тестовую базу. Приложение не доверяет
произвольным forwarded-заголовкам.

После успешной сборки проверьте вход, окно аккаунта и смену роли, сохранение оценки,
публикацию объявления, отправку и скачивание файла. Затем обновите страницу
и убедитесь, что записи сохранились.

## 4. Локальный сервер с той же Neon-базой

В `.env.local` оставьте `DATABASE_URL` той же базы, но задайте локальный Origin:

```dotenv
STUDYHUB_DEMO_MODE=true
STUDYHUB_ORIGIN=http://localhost:3000
```

```bash
npm run build
npm start
```

`npm start` запускает `next start`, который читает `.env.local`. Открывайте именно
[localhost:3000](http://localhost:3000); для `127.0.0.1` измените Origin соответственно.
Изменения локального и облачного приложения теперь попадают в одну Neon-базу.
Исходный SQLite-файл остаётся резервной копией и автоматически не обновляется.

Для изолированных локальных тестов `npm test` явно задаёт пустой `DATABASE_URL`
и временный каталог SQLite. До тестов нужна готовая сборка. Обычный локальный
SQLite-режим также остаётся доступен при пустом `DATABASE_URL`.

Проверка PostgreSQL запускается через `npm run test:postgres` на свежей отдельной
QA-ветке Neon. Её строка подключения хранится в приватном `.env.qa`; адрес базы
должен отличаться от `.env.local`. Проверка меняет данные, поэтому для повторного
запуска QA-ветку нужно заново создать или сбросить.

## Файлы и ограничения

Новые работы и материалы ограничены **3 МиБ** (3 × 1024 × 1024 байт).
Это оставляет место для multipart-обёртки в запросе к Vercel. Файлы хранятся
в приватной PostgreSQL-базе и выдаются только через API с проверкой прав.
Их объём учитывается в хранилище Neon; отдельная загрузка на публичный диск не используется.
