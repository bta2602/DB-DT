# StudyHUB

**Учебная информация в одном месте:** расписание, задания, оценки и посещаемость.

Учебный проект на **Next.js 16, React 19 и TypeScript**. Все страницы и серверные
API работают через Next.js App Router. Данные хранятся в отдельной SQLite-базе
на компьютере, а не в массиве внутри браузера.

## Зачем нужен StudyHUB

В учебной группе расписание, файлы заданий и оценки часто приходится искать
в разных местах. StudyHUB собирает эти сведения в одном личном кабинете.
Студент открывает свой учебный день, видит ближайшие пары и сроки сдачи,
получает материалы преподавателя и возвращается к результатам проверки.

Преподавателю доступна работа с назначенными ему группами и дисциплинами:
публикация задания, просмотр присланного файла, комментарий, оценка и отметка
посещаемости. Администратор поддерживает справочники и расписание, чтобы
страницы остальных пользователей показывали согласованные сведения.

Это учебная реализация электронного журнала и личного кабинета со
синтетическими данными для разработки и показа.

## Быстрый запуск для демонстрации

Нужен **Node.js 24+**. В терминале из папки проекта:

```bash
npm ci
npm run demo:setup
npm run dev
```

Откройте [localhost:3000](http://localhost:3000). При первом входе выберите
**«Студент»**, **«Преподаватель»** или **«Администратор»** в блоке
**«Учебный доступ»** на странице входа.

Дальше нажмите карточку пользователя **внизу левой боковой панели**:
откроется окно **«Аккаунт»** с выбором роли, кнопками «Открыть профиль»
и «Выйти из аккаунта». На телефоне сначала откройте боковое меню.
Выбор другой роли закрывает окно и открывает её кабинет без ввода пароля.

`demo:setup` создаёт `.env.local` и базу в соседней с проектом папке
`../studyhub-data/demo/`. Это отдельный каталог: база, файлы работ, пароли
и резервные копии не отправляются в GitHub. Повторный запуск не удаляет
внесённые изменения. Даты примеров выбираются относительно первого заполнения.

Для показа без разработки: `npm run build`, затем `npm start`.
Остановить сервер можно сочетанием **Ctrl+C** в его терминале.

## Что умеет сайт

| Роль          | Возможности                                                                                                                      |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| Студент       | Видит расписание своей группы, свои оценки и посещаемость; скачивает материалы, отправляет работы и читает результат проверки.   |
| Преподаватель | Создаёт задания и материалы для своих дисциплин, проверяет работы, ставит оценки и отмечает посещаемость своих групп.            |
| Администратор | Создаёт и редактирует пользователей, группы, предметы, аудитории и расписание; закрепляет преподавателей и публикует объявления. |
| Гость         | Читает страницу «О проекте», регистрируется или входит в аккаунт.                                                                |

Регистрация создаёт студента без группы. Администратор назначает группу
и при необходимости меняет роль. Обычный вход по почте и паролю сохранён.

Файлы работ и материалов: PDF, DOCX, ZIP, SQL, TXT, PNG, JPG и JPEG до 20 МБ.
Сервер проверяет формат, размер и право доступа. Оценки, работы и расписание
не исчезают после обновления страницы или перезапуска сервера.

## Разделы и учебный процесс

- **Сегодня** — ближайшие занятия, задания и общие объявления. Состав страницы
  зависит от роли пользователя.
- **Расписание** — занятия на день или неделю: предмет, преподаватель, группа,
  аудитория и время. Администратор создаёт, изменяет и отменяет занятия.
- **Предметы студента** — оценки за занятия и проверенные работы, посещаемость
  и доступные для скачивания материалы по выбранной дисциплине.
- **Задания студента** — условия, этапы выполнения, срок, загрузка файла
  и обратная связь. По статусу можно отделить несданные работы от проверенных.
- **Журнал преподавателя** — оценки и посещаемость по занятиям его групп.
  Изменения сохраняются на сервере, а устаревшая форма не перезаписывает
  более новую оценку другого запроса.
- **Проверка работ** — просмотр файла, оценка и комментарий либо возврат
  студенту на доработку с пояснением.
- **Мои задания преподавателя** — создание заданий и публикация материалов
  для назначенных предметов.
- **Кабинет администратора** — пользователи, группы, предметы, аудитории,
  назначения преподавателей, расписание и общие объявления.
  В списке пользователей доступны поиск по имени, почте и группе, фильтры
  роли и группы, страницы по 25 записей и общие счётчики.
- **Профиль и О проекте** — данные текущего аккаунта и описание платформы.

Типичный сценарий работы:

1. Администратор создаёт группу, предмет, преподавателя и аудиторию,
   назначает студентов группе и добавляет занятие в расписание.
2. Преподаватель публикует задание с условиями и будущим сроком сдачи.
3. Студент своей группы открывает задание и загружает выполненную работу.
4. Преподаватель скачивает или просматривает файл и сохраняет результат.
   При возврате на доработку студент может отправить исправленный файл.
5. Студент видит оценку и комментарий в своём кабинете. Изменения остаются
   в базе после выхода и следующего запуска сайта.

## Учебный набор данных

При подготовке новой базы создаются **320 студентов, 16 учебных групп,
16 преподавателей, 16 аудиторий и 12 предметов**, а также администратор.
Группы содержат по 20 студентов. Имена, почта, работы и результаты учёбы
вымышлены; они записываются в ту же структуру таблиц, что используется
для обычных аккаунтов.

Расписание рассчитано на четыре недели по будням, с утренней и дневной
сменами. Пара длится 80 минут, между парами одной смены — 20 минут.
Время показывается в часовом поясе Asia/Qyzylorda. Преподаватель, группа
и аудитория не должны занимать два занятия одновременно; аудитории
подбираются с учётом численности групп.

Команда заполнения также расширяет прежнюю небольшую учебную базу.
Существующие аккаунты, оценки, файлы и внесённые пользователем записи
сохраняются. При наличии ранее добавленных групп и пользователей общее число
может быть выше указанных значений. Повторный запуск не создаёт дубликаты.

## Технологии и устройство

| Технология         | За что отвечает                                             |
| ------------------ | ----------------------------------------------------------- |
| Next.js App Router | Маршруты страниц, серверная загрузка сессии и HTTP API.     |
| React              | Формы, таблицы, фильтры, диалоги и состояние интерфейса.    |
| TypeScript         | Типы страниц, компонентов и данных между интерфейсом и API. |
| Node.js 24         | Серверное выполнение и встроенный модуль `node:sqlite`.     |
| SQLite             | Связанные таблицы, сохранение данных, индексы и транзакции. |
| CSS                | Общие стили, цвета, компоновка и адаптация под телефон.     |
| ESLint и Prettier  | Проверка кода и единое форматирование.                      |
| `node:test`        | Автоматические сценарии для настоящего API и базы.          |

Браузер обращается к `/api/*` на том же адресе, где открыт сайт. Обработчик
Next.js проверяет сессию, роль и поля запроса, выполняет SQL-операцию
и возвращает ответ. После сохранения интерфейс перечитывает доступные
этому пользователю данные. Отдельный Express-сервер для проекта не нужен.

Пароли хранятся как хеши `scrypt`; случайный идентификатор сессии передаётся
в HttpOnly-cookie. Изменяющие запросы проверяются по Origin и CSRF-токену.
Студент не получает чужие работы и оценки через API. Права преподавателя
проверяются по назначенным предметам и группам, а не только по видимым кнопкам.

SQL-схема описывает пользователей, группы, дисциплины, аудитории, назначения,
занятия, задания, сдачи, оценки, посещаемость, материалы и объявления.
Содержимое загруженных файлов также лежит в приватной базе. Идентификаторы
связывают записи между собой; внешние ключи не позволяют сохранить ссылки
на несуществующие записи. При записи расписания проверяются пересечения
по группе, преподавателю и аудитории.

Страницы подключают свои React-компоненты через отдельные маршруты Next.js.
Общая оболочка с меню не импортирует все кабинеты сразу. После обычного
сохранения обновляются учебные данные без дополнительного запроса сессии;
запросы работ и оценок ограничиваются ролью на стороне SQL. Измерение скорости
под нагрузкой пока не проводилось.

## Структура проекта

```text
app/                    Страницы Next.js, layout, состояния загрузки и ошибок
  api/                  HTTP API: вход, данные, справочники, задания, файлы
  styles/               Общие стили и стили кабинетов
components/studyhub/    React-компоненты, формы, меню и переключатель ролей
lib/studyhub/           Серверная логика, права доступа, типы и общие функции
database/
  schema.mjs            Рабочая схема SQLite: таблицы, связи и индексы
  seeds/                Примеры только для команды заполнения базы
  design/               Первоначальный проект PostgreSQL команды
scripts/                Подготовка демонстрации и создание администратора
tests/                  Автоматическая проверка API и сохранения данных
docs/                   Архитектура, описание API, сценарий демонстрации
```

При настройке по этой инструкции данные лежат **за пределами этого дерева**. Их адрес задаётся
`STUDYHUB_DATA_DIR` в локальном файле настроек.

## Обычный режим

Для базы настоящих пользователей скопируйте `.env.example` в `.env.local`,
укажите **другой каталог данных** и оставьте `STUDYHUB_DEMO_MODE=false`.
Создайте первого администратора командой из таблицы. Она выведет путь
к приватному файлу со случайным паролем.

Выбор ролей доступен только в демонстрационном режиме. Сервер не разрешит
включить их на базе с обычными аккаунтами. В демонстрационную базу следует
вводить только вымышленные данные, поскольку в ней есть свободный вход администратора.

В интерфейсе используется обычное меню аккаунта, но данные начального набора
остаются синтетическими. Технические имена `demo:setup`, `demo:seed`
и `STUDYHUB_DEMO_MODE` обозначают этот изолированный режим. Переключатель
входит в три подготовленных аккаунта; он не меняет роль произвольного пользователя.

## Текущие ограничения

GitHub хранит исходники. Для этого приложения нужен работающий Node.js-сервер:
обычный GitHub Pages не запускает Next.js API и SQLite. Публикация в облаке
для текущей версии не настраивалась. SQLite требует постоянного каталога данных;
запуск нескольких независимых копий сервера с разными файлами базы не создаёт
общую систему автоматически.

Подтверждение почты, самостоятельное восстановление и смена пароля пока
не реализованы. При регистрации студент не выбирает себе группу и повышенную
роль: это делает администратор. Расписание заполняется вручную или командой
подготовки учебных примеров; импорта из внешних систем нет. Проверка расширения
и сигнатуры загружаемого файла не является антивирусной проверкой.

Функциональные тесты и ручной проход по интерфейсу описаны отдельно.
Нагрузочное тестирование и эксплуатация с реальными персональными данными
в рамках этого учебного проекта не подтверждались.
