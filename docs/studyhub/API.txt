StudyHUB — серверная интеграция (bta2602)

Исходники этой части:
lib/studyhub/api-contract.ts — типы DTO, маршруты и ограничения загрузок.
lib/studyhub/policy.mjs — функции прав доступа и проверки значений.

Реализованы регистрация, вход, выход, серверные сессии, профиль,
справочники, расписание, задания, оценки, посещаемость и проверка работ.
Требуется Node.js 24 или новее.
Аккаунты, сессии, учебные данные и файлы работ сохраняются
в .studyhub/auth.sqlite через node:sqlite.
Папка .studyhub исключена из Git. STUDYHUB_DATA_DIR позволяет изменить её путь.
Не размещать хранилище в public/ или на общем файловом ресурсе.

Рабочие маршруты:
GET /api/session, POST /api/auth/register, POST /api/auth/login,
POST /api/auth/logout, GET /api/bootstrap, PATCH /api/profile.
POST /api/users, /api/groups, /api/subjects, /api/rooms, /api/lessons;
PATCH /api/users/:id, /api/groups/:id, /api/subjects/:id,
/api/rooms/:id, /api/lessons/:id; PUT /api/teaching-assignments.
Bootstrap возвращает сохранённые данные, доступные текущей роли.
PUT /api/lessons/:id/grades/:studentId, PUT /api/lessons/:id/attendance,
PATCH /api/submissions/:id/review, POST /api/assignments,
POST /api/assignments/:id/submission, GET /api/files/:id.
Материалы и объявления читаются через Bootstrap.
PostgreSQL-миграция database/migrations/001_initial.sql к локальной
SQLite-базе не применяется: это отдельная будущая интеграция.

РЕГИСТРАЦИЯ И СОЗДАНИЕ АДМИНИСТРАТОРА

POST /api/auth/register принимает {name,email,password,passwordConfirmation}.
Имя — до 120 символов; почта — до 254; пароль — от 12 до 128 символов.
Пароль и повтор должны совпадать. Публичная регистрация всегда создаёт
студента без группы; назначить себе преподавателя или администратора нельзя.
После успешной регистрации пользователь сразу получает сессию.
Подтверждение почты и восстановление пароля пока не реализованы.

Первый администратор создаётся локальной командой на сервере:
npm run admin:create -- admin@example.com "Имя администратора"
Команда генерирует отдельный случайный пароль и сохраняет его в приватном
файле admin-access-*.txt внутри каталога данных. В самой базе хранится
только scrypt-хеш. Повторный запуск не сбрасывает пароль существующему админу.

Запуск на этом компьютере: npm run dev -- --hostname 127.0.0.1
Открыть http://127.0.0.1:3000/.
Для размещения снаружи нужны HTTPS, STUDYHUB_ORIGIN с адресом сайта,
постоянный приватный том для базы; серверные копии не должны иметь отдельные базы.

ПОДКЛЮЧЕНИЕ FRONTEND

Frontend: страницы app/*/page.tsx, React-компоненты components/studyhub/, стили app/styles/. Интерфейс обращается к /api/*
того же origin.

GET /api/session возвращает:
{ user: null | User, csrfToken: string }

Роль определяется проверенной серверной сессией.
При регистрации и входе роль из URL или тела запроса не принимается.
Назначать роли через /api/users может только действующий администратор.

GET /api/bootstrap возвращает все массивы типа Bootstrap,
в том числе пустые массивы, если данных пока нет.

Каждый запрос проверяет сессию, роль пользователя и назначение
преподавателя группе и предмету.

Ограничения доступа применяются на сервере.
Полная БД клиенту не передаётся.

СЕССИИ И ОТВЕТЫ

Серверные сессии хранить в HttpOnly-cookie.
Для HTTPS использовать Secure.

Проверять Origin и CSRF.
Frontend отправляет X-CSRF-Token при изменениях.

Пароли, ключи, токены и .env с секретами в Git не добавлять.
В DTO пользователей не включать хеши паролей или данные сессий.

Успешные изменения возвращают:
{ "ok": true }

После успешной записи UI перечитывает /api/bootstrap.

Ошибки возвращаются в формате:
{
  "error": {
    "code": "ERROR_CODE",
    "message": "Сообщение пользователю",
    "fields": {
      "fieldName": "Ошибка поля"
    }
  }
}

fields — необязательное поле.

HTTP-статусы:
401 — требуется вход;
403 — недостаточно прав;
409 — конфликт версии или расписания;
422 — некорректные данные;
5xx — ошибка сервера.

ВЕРСИИ И СОХРАНЕНИЕ

Версии записей обязательны.
При конфликте вернуть 409 без перезаписывания чужих изменений.

Проверку версии и изменение записи выполнять атомарно в БД.

Снятая оценка остаётся в Bootstrap как grade: null
с актуальной version.

version: null в запросе оценки означает,
что записи оценки ещё не было.

Посещаемость сохраняется одной транзакцией
по lesson.attendanceVersion.

Оценка и обратная связь относятся к конкретной сдаче,
а не ко всему заданию.

ЗАГРУЗКА РАБОТ

Максимальный размер файла: 20 МБ.

Разрешённые расширения:
PDF, DOCX, ZIP, SQL, TXT, PNG, JPG, JPEG.

Размер, формат, содержимое и права проверяются на сервере.

Файлы хранить вне public/ под непредсказуемыми ключами.
Текущая реализация хранит содержимое в приватной SQLite-базе. Расширение,
размер, UTF-8 для текстовых файлов и начальная сигнатура бинарных форматов
проверяются при загрузке; это не антивирусная проверка содержимого.

GET /api/files/:id каждый раз проверяет доступ.

При повторной сдаче создавать новый fileId,
чтобы клиент не получил старую версию файла.

РАСПИСАНИЕ И СПРАВОЧНИКИ

Дата и время передаются в ISO-формате с часовым поясом.
UI отображает время в Asia/Qyzylorda.

Пересечения группы, преподавателя и аудитории проверяются
на сервере и в БД, включая одновременные запросы.

Допустимый курс группы: от 1 до 6.

Все изменения справочников и расписания доступны только администратору;
сервер проверяет актуальную роль, Origin, CSRF, ссылки и версии записей.
Новая схема добавляется автоматически с сохранением существующих аккаунтов.
Обновление страницы и перезапуск сервера не удаляют данные из файла базы.

Порядок настройки через интерфейс:
1. Пользователи и группы → Группы: создать группу.
2. Там же → Предметы: добавить предмет.
3. Там же → Пользователи: создать преподавателя с почтой и паролем
   от 12 до 128 символов; либо изменить роль зарегистрированного пользователя.
4. Аудитории: добавить помещение.
5. Расписание → Добавить занятие: выбрать записи и время, сохранить.
Кнопка добавления занятия также показывает недостающие записи и открывает
их создание. Выдуманные преподаватели и занятия автоматически не добавляются.
Сохранение занятия добавляет назначение преподавателя на выбранные
группу и предмет; расписание становится доступно ему и студентам группы.

POST /api/users принимает {name,email,role,groupId,password}.
PATCH /api/users/:id принимает {name,email,role,groupId,version}, без пароля.
Пароль нового пользователя задаётся администратором и хранится как scrypt-хеш.
Регистрация остаётся доступной только для роли student. Восстановление
и смена пароля через интерфейс пока не реализованы.

Каждое редактирование требует version из Bootstrap, включая предметы.
Занятие можно отменить или восстановить через PATCH с {status,version}.
Отменённые занятия не занимают время. При восстановлении пересечения
проверяются заново. Проверка пересечений и запись выполняются в одной
транзакции; занятия могут следовать друг за другом без перерыва.

ДЕМОНСТРАЦИОННЫЕ ДАННЫЕ

npm run demo:seed добавляет вымышленные группы, преподавателей, студентов,
расписание, задания, работы, оценки, посещаемость и материалы в текущую базу.
Перед заполнением создаётся приватная резервная копия в .studyhub/backups/.
Существующие записи и администратор сохраняются. Повторный запуск не меняет
созданные примеры, выставленные оценки и пароли.
Данные для входа находятся в .studyhub/demo-access-*.json, исключённом из Git.
Поле teacher содержит основной аккаунт преподавателя, student — студента.
Подробный порядок показа проекта: docs/studyhub/DEMO.txt.
Дополнительный набор: npm run demo:seed -- --more. Он дополняет данные
отдельным пакетом, сохраняя старые записи и пароли. Повторный запуск
не создаёт дубликатов. Новые пароли — в .studyhub/demo-access-more-*.json.
