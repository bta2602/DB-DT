# API StudyHUB

API находится на том же адресе, что и сайт. Типы ответов описаны
в `lib/studyhub/api-contract.ts`, обработчики — в `app/api/`.
Сайт работает на Node.js 24.x. При заданном `DATABASE_URL` API использует
PostgreSQL в Neon; локально при пустом значении — SQLite. На Vercel
`DATABASE_URL` обязателен. Контракт запросов и проверка прав одинаковы для обеих баз.

Новые учебные правила требуют миграции `academic_rules_v1` до запуска этой версии
с PostgreSQL. Порядок подготовки базы и границы выполненной части описаны
в [памятке по backend](BACKEND-ACADEMIC.md). Эта версия ещё не развёрнута,
миграция рабочей базы не выполнялась.

## Сессия

`GET /api/session` создаёт гостевую сессию при необходимости и возвращает:

```json
{ "user": null, "csrfToken": "...", "demoEnabled": true }
```

После входа `user` содержит id, имя, почту, роль, группу и версию записи.
Пароль, его хеш и идентификатор cookie в JSON не передаются.

Все изменяющие запросы отправляют cookie сессии, заголовок
`X-CSRF-Token` и правильный `Origin`. JSON-запросы используют
`Content-Type: application/json`. Для файлов используется `FormData`;
Content-Type с границей multipart выставляет браузер.

| Метод и путь            | Назначение / тело                                               |
| ----------------------- | --------------------------------------------------------------- |
| POST /api/auth/register | `name, email, password, passwordConfirmation`; создаёт студента |
| POST /api/auth/login    | `email, password`                                               |
| POST /api/auth/logout   | Пустой объект                                                   |
| POST /api/auth/demo     | `role: student / teacher / admin`; только в деморежиме          |
| GET /api/bootstrap      | Все доступные этой роли учебные массивы                         |
| PATCH /api/profile      | `name, version`                                                 |

Пароль регистрации — от 12 до 128 символов. Назначить себе роль преподавателя
через регистрацию нельзя. Демо-вход выбирает фиксированный аккаунт и обновляет
сессию; его наличие определяется серверной настройкой и типом базы.

## Администратор

| Метод и путь                  | Поля                                                                         |
| ----------------------------- | ---------------------------------------------------------------------------- |
| POST /api/users               | `name, email, role, groupId, password`                                       |
| PATCH /api/users/:id          | `name, email, role, groupId, version`                                        |
| POST /api/groups              | `name, course, curatorId`; дополнительно `program, intakeYear, language`     |
| PATCH /api/groups/:id         | Поля группы и `version`                                                      |
| POST /api/subjects            | `name`                                                                       |
| PATCH /api/subjects/:id       | `name, version`                                                              |
| POST /api/rooms               | `name, capacity`; дополнительно `number, floor, type`                        |
| PATCH /api/rooms/:id          | Поля аудитории и `version`                                                   |
| PUT /api/teaching-assignments | `teacherId, groupId, subjectId`; необязательная `date` для проверки семестра |
| POST /api/lessons             | `subjectId, groupId, teacherId, kind`; поля времени или связи СРСП — ниже    |
| PATCH /api/lessons/:id        | Изменяемые поля занятия и `version`                                          |
| POST /api/announcements       | `title, body`                                                                |
| DELETE /api/announcements/:id | Пустой объект                                                                |

`program` группы — `IS`, `VTIPO` или `DS`; `language` — `kk` или `ru`.
Если задан `intakeYear`, курс вычисляется из года поступления и текущего учебного
года; допустимы курсы 1–6. Без `intakeYear` сохраняется прежнее поле `course`.
У аудитории `number` — строка, `floor` — целое число 1–100, `type` —
`computer`, `lecture`, `laboratory` или `ordinary`.
Новые поля могут быть `null` у старых записей. Названия групп и аудиторий
миграция автоматически не меняет.

Вместимость аудитории — 1–1000 или `null` в справочнике, но для сохранения
обычного занятия она должна быть известна и вмещать всех студентов группы.

### Специализация преподавателей и учебные планы

Эти запросы доступны только администратору:

| Метод и путь                        | Тело запроса                                            |
| ----------------------------------- | ------------------------------------------------------- |
| PUT /api/academic/teacher-subjects  | `teacherId, subjectIds: string[]`                       |
| PUT /api/academic/teacher-languages | `teacherId, languages: ("kk" \| "ru")[]`                |
| PUT /api/academic/group-subjects    | `groupId, academicYear, semester, subjectIds: string[]` |

Каждый `PUT` **полностью заменяет список в указанной области**:
предметы одного преподавателя, языки одного преподавателя или предметы одной
группы в одном учебном году и семестре. Остальные преподаватели, группы и
семестры не меняются. Значения в списке должны быть уникальными; `[]` очищает
этот список. Передавать только добавляемый предмет нельзя: остальные связи
будут удалены. Все изменения одного запроса выполняются в транзакции.

У этих трёх запросов нет поля `version` и проверки оптимистической блокировки:
параллельные записи выполняются последовательно, последний допустимый запрос
заменяет результат предыдущего. Перед редактированием перечитайте полный список
из `bootstrap`; не отправляйте сохранённую ранее копию как добавление одного элемента.

У преподавателя может быть не более трёх предметов и двух языков.
В учебном плане группы допускается до 100 предметов; `academicYear` — год начала
учебного года, `semester` — `1` или `2`. В принятой модели сентябрь–декабрь —
первый семестр, январь–август — второй: например, `2027-02-15` относится
к `academicYear: 2026, semester: 2`.

Удаление связи, необходимой действующему или будущему неотменённому занятию,
отклоняется с `409 ACADEMIC_ASSIGNMENT_IN_USE`. Сначала нужно изменить расписание.
Для СРСП учитывается дата связанной практики.

Перед назначением преподавателя группе сервер проверяет его предметы,
язык обучения группы и её учебный план. В `PUT /api/teaching-assignments`
можно передать `date: "2026-11-16"`; без неё проверяется текущая дата кампуса.
Создание занятия дополнительно требует уже существующей связи
`teacherId + groupId + subjectId`; автоматически такая связь не создаётся.

`GET /api/bootstrap` дополнен массивами:

- `teacherSubjects`: `{ teacherId, subjectId }`;
- `teacherLanguages`: `{ teacherId, language }`;
- `groupSubjects`: `{ groupId, subjectId, academicYear, semester }`.

Миграция создаёт пустые таблицы этих связей. Существующие учебные записи остаются
доступны для чтения, но новые занятия и задания требуют настройки назначений.

### Занятия и СРСП

Для лекции или практики отправляйте `kind: "lecture"` или `"practice"`,
`roomId`, `date: "YYYY-MM-DD"` и `slotId`. Сервер вычисляет `startsAt` и `endsAt`
с учётом времени кампуса UTC+5 (Asia/Qyzylorda).

| slotId | Время       |
| ------ | ----------- |
| p1     | 08:00–08:50 |
| p2     | 08:55–09:45 |
| p3     | 09:50–10:40 |
| p4     | 10:55–11:45 |
| p5     | 11:50–12:40 |
| p6     | 12:45–13:35 |
| p7     | 13:50–14:40 |
| p8     | 14:45–15:35 |
| p9     | 15:40–16:30 |
| p10    | 16:45–17:35 |
| p11    | 17:40–18:30 |
| p12    | 18:35–19:25 |

После третьей, шестой и девятой пары перерыв составляет 15 минут, между остальными — 5.
Для существующей PostgreSQL-базы расширение сетки применяется отдельной миграцией
`evening_slots_v1`; она сохраняет записи и обновляет ограничение слотов и проверки времени.
Старый формат `startsAt, endsAt` с часовым поясом принимается для записи только
при точном совпадении с одной из пар. При одновременной передаче даты, слота
и временных меток они должны совпадать. При изменении даты или слота удобнее
отправлять только изменяемые поля и `version`, без прежних временных меток.
Исторические занятия вне этой сетки остаются читаемыми; их можно отменять
или менять примечание без переноса на новую сетку.

Для СРСП отправляйте `kind: "srsp"` и `practiceId` активной практики той же
группы и предмета. Отдельные аудитория, слот и время не задаются: `roomId`,
`slotId`, `startsAt`, `endsAt` должны отсутствовать или быть `null`.
Дату сервер берёт из практики; если `date` передана, она обязана совпасть с ней.
В ответе `Lesson.date` присутствует у всех занятий, а указанные четыре поля
для СРСП равны `null`. При переносе практики дата СРСП меняется вместе с ней.

СРСП не занимает аудиторию или отдельный интервал расписания и не имеет
самостоятельной отметки посещаемости или ячейки журнала. При отмене практики
связанная СРСП возвращается как `cancelled`; восстановление практики снова
проверяет учебные назначения и конфликты. Уже опубликованное задание СРСП,
его срок сдачи и доступность сдачи работы сохраняются при отмене практики.
Это позволяет не терять ранее выданную учебную работу; новый срок автоматически
не устанавливается и при переносе практики.

Сервер запрещает пересечения группы, преподавателя и аудитории для обычных
неотменённых занятий. Проверка и запись выполняются в одной транзакции.
Для восстановления отменённого занятия эти проверки выполняются повторно.
Связанные СРСП, задания и оценки также ограничивают изменение группы,
предмета или типа существующего занятия, чтобы не нарушить их принадлежность.

### Доступность аудиторий

```text
GET /api/rooms/availability?date=2026-11-16&slotId=p1&groupId=<id>
```

Все три параметра обязательны. Администратор может выбрать любую группу,
преподаватель — назначенную ему группу, студент — свою. При редактировании
занятия администратор может добавить `excludeLessonId`, чтобы не считать
это занятие конфликтом с самим собой. Неизвестные или повторяющиеся параметры
отклоняются с `422 INVALID_QUERY`.

Ответ содержит все аудитории без сведений о чужих группах или преподавателях:

```json
{
  "rooms": [{ "roomId": "room-101", "available": true, "capacityOk": true, "busyUntil": null }]
}
```

`available` означает отсутствие занятия, пересекающего выбранную пару.
`capacityOk` отдельно проверяет вместимость для состава выбранной группы;
при неизвестной вместимости он равен `false`. Для занятой аудитории `busyUntil`
содержит наиболее поздний конец пересекающихся занятий в ISO, иначе `null`.
Это предварительная проверка: сохранение занятия повторно проверяет
вместимость и пересечения, поскольку расписание могло измениться.

## Преподаватель и студент

| Метод и путь                           | Доступ и поля                                                                                                   |
| -------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| POST /api/assignments                  | Преподаватель; `lessonId, title, description, steps, groupId, subjectId, teacherId, dueAt`; `type` необязателен |
| POST /api/assignments/:id/submission   | Студент; multipart с одним `file`                                                                               |
| PATCH /api/submissions/:id/review      | Преподаватель; `action, grade, comment, version`                                                                |
| PUT /api/lessons/:id/grades/:studentId | Преподаватель; `grade, status, version`                                                                         |
| PUT /api/lessons/:id/attendance        | Преподаватель; `entries, version`                                                                               |
| POST /api/materials                    | Преподаватель; multipart `subjectId, title, file`                                                               |
| DELETE /api/materials/:id              | Преподаватель назначенного предмета или администратор; пустой объект                                            |
| GET /api/files/:id                     | Только пользователь с доступом к работе или материалу                                                           |

Преподаватель работает со своими назначенными предметами и группами.
Студент видит только собственные оценки и работы. Материалы и объявления
читаются через `bootstrap`.

Новое задание обязательно связано с активным занятием через `lessonId`.
Преподаватель должен вести это занятие, а группа и предмет задания — совпадать
с его группой и предметом. Тип определяется сервером по занятию: `lecture`,
`practice` или `srsp`. Если клиент передаёт `type`, значение должно совпасть.
Для СРСП дополнительно проверяется активная связанная практика. Проверяются
также специализация, язык и учебный план на дату занятия. `dueAt` — отдельный
будущий срок сдачи в ISO с часовым поясом.

Старые задания с `lessonId: null` остаются доступными для просмотра и сдачи.
Для новых публикаций отсутствие `lessonId` возвращает `422 LESSON_REQUIRED`.

Максимальный файл — 3 МиБ (3 × 1024 × 1024 байт); разрешены PDF, DOCX, ZIP, SQL, TXT, PNG, JPG, JPEG.
Проверяются расширение, сигнатура бинарного формата, UTF-8 текстов, размер
и права. Это проверка формата, а не антивирус. Содержимое файлов хранится
в приватной базе: `bytea` в PostgreSQL, `BLOB` в локальном SQLite. Файлы
не публикуются в `public/` и скачиваются через API с исходным именем.

## Ответы и конфликты

Успех: `{ "ok": true }`. Вход также возвращает новый `csrfToken`.
После изменения клиент обновляет `/api/bootstrap`.

Ошибка:

```json
{
  "error": {
    "code": "VERSION_CONFLICT",
    "message": "Запись уже изменена. Обновите страницу.",
    "fields": {}
  }
}
```

| Статус | Смысл                                                   |
| ------ | ------------------------------------------------------- |
| 401    | Нужно войти                                             |
| 403    | Недостаточно прав или неверный CSRF/Origin              |
| 404    | Запись не найдена или деморежим выключен                |
| 409    | Конфликт версии, почты или расписания                   |
| 413    | Превышен размер запроса/файла                           |
| 415    | Ожидался JSON или multipart с файлом                    |
| 422    | Ошибка полей или формата                                |
| 429    | Слишком много попыток                                   |
| 503    | Ошибка настройки режима или ещё не загружены демоданные |

`version` берётся из последнего `bootstrap`. Для новой оценки передаётся
`version: null`; для посещаемости — `lesson.attendanceVersion`.
Снятая оценка хранится как `grade: null, status: "unmarked"` с обновлённой версией.
Запись и проверка версии выполняются в одной транзакции.

Учебные проверки могут вернуть `422 ACADEMIC_SETUP_REQUIRED`,
`TEACHER_SUBJECT_NOT_ALLOWED`, `TEACHER_LANGUAGE_NOT_ALLOWED`,
`SUBJECT_NOT_IN_CURRICULUM`, `TEACHING_ASSIGNMENT_REQUIRED`, `ROOM_CAPACITY`,
`INVALID_SLOT`, `INVALID_PRACTICE` или `SRSP_INHERITS_PRACTICE`.
Клиенту следует показывать `error.message` и связанные `error.fields`.
Конфликт версии требует обновления данных перед повторной отправкой.

## Единый журнал и шкала 0–100

Запись `Grade` содержит `status`, `grade` и `version`:

| status       | grade             | Отображение                    |
| ------------ | ----------------- | ------------------------------ |
| graded       | целое число 0–100 | Балл                           |
| absent       | null              | Н — отсутствует                |
| not_required | null              | н.п. — оценка не предусмотрена |
| unmarked     | null              | Пустая ячейка                  |

Нельзя одновременно отправить числовой балл и нечисловой статус. В среднем
участвуют только числовые оценки, включая 0. Проверка работы также принимает
целое число 0–100. Старый запрос без `status` совместим: число означает `graded`,
`null` означает `unmarked`. Исторический attendance API оставлен для совместимости,
но отдельной формы посещаемости нет. Он не заменяет уже выставленные баллы и н.п.
В нём `absent` и `excused` ставят Н, если ячейка пуста или уже содержит Н;
`present`, `late` и снятие отметки очищают только Н. Создать н.п. можно только
запросом оценки с `status: "not_required"`.
Для отдельной СРСП оба запроса — оценки и посещаемости — отклоняются
с `422 SRSP_NO_ATTENDANCE`; оценивать можно сданную работу через проверку задания.
Изменение ячейки увеличивает также `attendanceVersion`, чтобы старая форма
посещаемости не могла перезаписать свежую отметку журнала.

Примеры тела `PUT /api/lessons/:id/grades/:studentId` для новой записи:

```json
{ "grade": 0, "status": "graded", "version": null }
```

```json
{ "grade": null, "status": "not_required", "version": null }
```

При последующих изменениях передавайте актуальную `Grade.version`, а не `null`.
После обновления серверной схемы прежние оценки 2–5 уже преобразованы в 40–100;
новый запрос с числом 5 означает именно **5 из 100** и больше не пересчитывается.
