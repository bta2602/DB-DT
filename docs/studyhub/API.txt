StudyHUB — серверная интеграция (bta2602)

Исходники этой части:
lib/studyhub/api-contract.ts — типы DTO, маршруты и ограничения загрузок.
lib/studyhub/policy.mjs — функции прав доступа и проверки значений.

Авторизация реализована локально: регистрация, вход, выход, серверные сессии,
чтение профиля и изменение имени. Требуется Node.js 24 или новее.
Данные аккаунтов и сессий сохраняются в .studyhub/auth.sqlite через node:sqlite.
Папка .studyhub исключена из Git. STUDYHUB_DATA_DIR позволяет изменить её путь.
Не размещать хранилище в public/ или на общем файловом ресурсе.

Рабочие маршруты:
GET /api/session, POST /api/auth/register, POST /api/auth/login,
POST /api/auth/logout, GET /api/bootstrap, PATCH /api/profile.
Bootstrap возвращает реальных пользователей, доступных текущей роли;
учебные массивы пока пустые. Расписание, задания, оценки, загрузки и
управление справочниками ещё требуют подключения полноценного backend.
PostgreSQL-миграция database/migrations/001_initial.sql к локальной
SQLite-базе авторизации не применяется: это отдельная будущая интеграция.

РЕГИСТРАЦИЯ И СОЗДАНИЕ АДМИНИСТРАТОРА

POST /api/auth/register принимает {name,email,password,passwordConfirmation}.
Имя — до 120 символов; почта — до 254; пароль — от 12 до 128 символов.
Пароль и повтор должны совпадать. Публичная регистрация всегда создаёт
студента без группы; назначить себе преподавателя или администратора нельзя.
После успешной регистрации пользователь сразу получает сессию.
Подтверждение почты и восстановление пароля пока не реализованы.

Администратор создаётся только локальной командой на сервере:
npm run admin:create -- admin@example.com "Имя администратора"
Команда генерирует отдельный случайный пароль и сохраняет его в приватном
файле admin-access-*.txt внутри каталога данных. В самой базе хранится
только scrypt-хеш. Повторный запуск не сбрасывает пароль существующему админу.

Запуск на этом компьютере: npm run dev -- --hostname 127.0.0.1
Открыть http://127.0.0.1:3000/studyhub/index.html.
Для размещения снаружи нужны HTTPS, STUDYHUB_ORIGIN с адресом сайта,
постоянный приватный том для базы и
завершение учебного backend; серверные копии не должны иметь отдельные базы.

ПОДКЛЮЧЕНИЕ FRONTEND

Frontend расположен в public/studyhub/ и обращается к /api/*
того же origin.

GET /api/session возвращает:
{ user: null | User, csrfToken: string }

Роль определяется проверенной серверной сессией.
Роль из URL или тела запроса не назначается.

GET /api/bootstrap возвращает все массивы типа Bootstrap,
в том числе пустые массивы, если данных пока нет.

Каждый запрос проверяет сессию, роль пользователя и назначение
преподавателя группе и предмету.

Ограничения доступа применяются на сервере.
Полная БД клиенту не передаётся.

СЕССИИ И ОТВЕТЫ

Серверные сессии хранить в HttpOnly-cookie.
Для HTTPS использовать Secure.

Проверять Origin и CSRF.
Frontend отправляет X-CSRF-Token при изменениях.

Пароли, ключи, токены и .env с секретами в Git не добавлять.
В DTO пользователей не включать хеши паролей или данные сессий.

Успешные изменения возвращают:
{ "ok": true }

После успешной записи UI перечитывает /api/bootstrap.

Ошибки возвращаются в формате:
{
  "error": {
    "code": "ERROR_CODE",
    "message": "Сообщение пользователю",
    "fields": {
      "fieldName": "Ошибка поля"
    }
  }
}

fields — необязательное поле.

HTTP-статусы:
401 — требуется вход;
403 — недостаточно прав;
409 — конфликт версии или расписания;
422 — некорректные данные;
5xx — ошибка сервера.

ВЕРСИИ И СОХРАНЕНИЕ

Версии записей обязательны.
При конфликте вернуть 409 без перезаписывания чужих изменений.

Проверку версии и изменение записи выполнять атомарно в БД.

Снятая оценка остаётся в Bootstrap как grade: null
с актуальной version.

version: null в запросе оценки означает,
что записи оценки ещё не было.

Посещаемость сохраняется одной транзакцией
по lesson.attendanceVersion.

Оценка и обратная связь относятся к конкретной сдаче,
а не ко всему заданию.

ЗАГРУЗКА РАБОТ

Максимальный размер файла: 20 МБ.

Разрешённые расширения:
PDF, DOCX, ZIP, SQL, TXT, PNG, JPG, JPEG.

Размер, формат, содержимое и права проверяются на сервере.

Файлы хранить вне public/ под непредсказуемыми ключами.

GET /api/files/:id каждый раз проверяет доступ.

При повторной сдаче создавать новый fileId,
чтобы клиент не получил старую версию файла.

РАСПИСАНИЕ И СПРАВОЧНИКИ

Дата и время передаются в ISO-формате с часовым поясом.
UI отображает время в Asia/Qyzylorda.

Пересечения группы, преподавателя и аудитории проверяются
на сервере и в БД, включая одновременные запросы.

Допустимый курс группы: от 1 до 6.

Регистрация создаёт аккаунты студентов. Админский аккаунт создаётся
локальной командой admin:create. Управление ролями, выдача доступа
преподавателям и восстановление пароля требуют дальнейшей реализации.
