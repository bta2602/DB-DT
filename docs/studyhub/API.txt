StudyHUB — серверная интеграция (bta2602)

Готовые исходники этой части:
lib/studyhub/api-contract.ts — типы DTO, маршруты и ограничения загрузок.
lib/studyhub/policy.mjs — чистые функции прав доступа и проверки значений.
tests/backend/policy.test.mjs — тесты этих функций.

Это контракт и правила для реализации сервера. Здесь нет HTTP route handlers,
проверки паролей, серверных сессий и подключённой БД.
Полноценный сервер команда подключает отдельно, как было согласовано.

Frontend расположен в public/studyhub/ и обращается к /api/* того же origin.
GET /api/session возвращает {user:null|User,csrfToken}; роль из URL не назначается.
GET /api/bootstrap возвращает все массивы Bootstrap, в том числе пустые.
Каждый запрос должен проверять сессию, роль и назначение группы/предмета.
Нельзя отдавать полную БД клиенту и полагаться только на фильтры браузера.

Серверные сессии хранить в HttpOnly-cookie. Для HTTPS использовать Secure.
Проверять Origin/CSRF; frontend отправляет X-CSRF-Token при изменениях.
Пароли, ключи, токены и .env с секретами в Git не добавлять.
Успешные изменения возвращают {ok:true}; UI после этого перечитывает Bootstrap.
Ошибки возвращаются как {error:{code,message,fields?}} с HTTP 401/403/409/422/5xx.

Версии обязательны. При конфликте вернуть 409 без тихого перезаписывания.
Снятая оценка остаётся в Bootstrap как grade:null с актуальной version.
version:null означает, что записи оценки ещё не было.
Посещаемость сохраняется одной транзакцией по lesson.attendanceVersion.
Оценка и обратная связь относятся к конкретной сдаче, не ко всему заданию.

Файл сдачи: до 20 МБ, PDF/DOCX/ZIP/SQL/TXT/PNG/JPG/JPEG. Проверять размер,
формат, содержимое и права на сервере. Объекты хранить вне public/ под
непредсказуемыми ключами. GET /api/files/:id каждый раз проверяет доступ.
При повторной сдаче создавать новые fileId, чтобы не вернуть старый файл.

Расписание передаёт ISO-время с часовым поясом; UI отображает Asia/Qyzylorda.
Проверять пересечения на сервере и в БД, включая одновременные запросы.
Course: 1–6. Администратор создаёт учётные записи без передачи паролей через UI;
за выдачу доступа и восстановление пароля отвечает отдельный серверный процесс.

Проверка из корня репозитория:
node --test tests/backend/policy.test.mjs
