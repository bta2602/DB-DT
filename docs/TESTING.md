# Проверка StudyHUB

## Команды

Нужен Node.js 24+. После установки зависимостей выполните из папки проекта:

```bash
npm run lint
npm run build
npm test
```

`npm test` использует последнюю готовую сборку. После изменения кода сначала
повторите `npm run build`. Форматирование отдельно проверяется командой
`npm run format:check`.

На проверке **3 ноября 2026 года** ESLint, сборка TypeScript/Next.js и весь
описанный ниже автоматический прогон прошли успешно.

## Как устроен автоматический прогон

`tests/run-api.mjs` создаёт новую временную папку и отдельную базу SQLite,
заполняет её учебными примерами и запускает собранный Next.js на свободном
локальном порту. Рабочая база, демонстрационная база для показа и `.env.local`
не изменяются.

После проверок сервер останавливается. При успехе временные данные удаляются;
при ошибке путь к оставленной тестовой базе выводится в терминал для разбора.
Тесты не подключаются к внешнему сайту и не требуют дополнительных библиотек.

| Файл                     | Назначение                                                              |
| ------------------------ | ----------------------------------------------------------------------- |
| `tests/http-client.mjs`  | HTTP-клиент с cookie, CSRF-токеном и отправкой файлов.                  |
| `tests/api.test.mjs`     | 16 последовательных сценариев через настоящий HTTP API.                 |
| `tests/storage.test.mjs` | Изоляция обычных аккаунтов от демонстрационного переключения ролей.     |
| `tests/run-api.mjs`      | Подготовка базы, запуск/остановка сервера и проверка сохранения данных. |

В выводе API-прогона Node показывает **17 тестов**: 16 сценариев и один
объединяющий тест. Две проверки хранилища запускаются отдельно: изоляция обычной базы и защита ролей трёх закреплённых демоаккаунтов.

## Что проверено автоматически

| Область         | Проверки                                                                                                                             |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Сессии          | Гостевая сессия, HttpOnly/SameSite-cookie, запрет доступа без входа, смена сессии и CSRF при переключении роли.                      |
| Деморежим       | Вход во все три роли; отказ для неизвестной роли, неверного Origin и CSRF; отключение переключателя серверной настройкой.            |
| Изоляция баз    | Попытка включить деморежим на базе обычного пользователя отклоняется; исходный аккаунт и его сессия сохраняются.                     |
| Навигация       | HTTP-ответы всех 15 страниц, прежний адрес `/studyhub/index.html` и ответ 404 для неизвестной страницы.                              |
| Справочники     | Создание преподавателя, студентов, группы, предмета и аудитории; назначение преподавателя; редактирование и проверка значений.       |
| Роли аккаунтов  | Изменение роли администратором, отражение новой роли в действующей сессии, отказ при устаревшей версии записи.                       |
| Расписание      | Создание, отмена, восстановление; запрет пересечения и неправильного интервала; разрешение соседних занятий.                         |
| Оценки          | Сохранение, изменение и снятие оценки; конфликт версии; запрет студенту выставлять оценки; отсутствие чужих оценок в ответе.         |
| Посещаемость    | Сохранение и снятие отметки, конфликт версии, запрет изменения студентом.                                                            |
| Задания         | Публикация преподавателем, появление у студента, проверка срока и прав.                                                              |
| Сдача работы    | Загрузка настоящего SQL-файла, проверка сохранённого содержимого, отклонение пустого/неподдерживаемого файла и ложного PDF.          |
| Проверка работы | Возврат на доработку, повторная сдача с новым файлом, оценка и комментарий, результат в кабинете студента.                           |
| Доступ к файлам | Работу скачивает её преподаватель; другой студент и гость доступа не получают; старый заменённый файл недоступен.                    |
| Материалы       | Публикация файла преподавателем, скачивание студентом, удаление; запрет публикации и удаления студентом.                             |
| Объявления      | Публикация и удаление администратором, чтение студентом, запрет изменения преподавателем.                                            |
| Профиль и вход  | Изменение имени, конфликт версии, регистрация, вход и выход, неверный пароль, повторная почта, запрет назначить себе администратора. |

После HTTP-сценариев тестовый сервер **перезапускается**, а заполнение базы
выполняется повторно. Проверяется сохранение сессии и точное совпадение
учебных данных до и после перезапуска. Затем сервер запускается с выключенным
деморежимом: API переключения ролей должен отказать.

## Проверка в браузере

HTTP-тесты проверяют серверные сценарии и доступность страниц. Они не нажимают
кнопки и не подтверждают правильность расположения элементов. Поэтому формы,
диалоги, адаптацию и навигацию также проверяем вручную в браузере.

В текущем ручном проходе подтверждены:

- открытие мобильного меню;
- разделы предмета студента: оценки, посещаемость, материалы;
- скачивание материала;
- фильтр заданий;
- выбор настоящего SQL-файла и отправка работы с сохранением статуса;
- переключение между всеми тремя ролями;
- открытие отправленного SQL-файла, оценка и комментарий преподавателя, результат у студента;
- выставление оценки в журнале, массовая отметка посещаемости и её сохранение;
- день/неделя и фильтр группы в расписании;
- формы создания пользователя, группы, предмета, назначения, аудитории и занятия;
- форма редактирования аудитории, закрытие диалогов кнопкой и Escape;
- публикация объявления и его появление у студента;
- публикация материала, окно подтверждения удаления и отмена удаления;
- профиль, страница «О проекте», выход, регистрационная форма и переключатель видимости пароля;
- расположение элементов на ширинах 390 и 1280 пикселей.

Для повторения используйте [сценарий показа](DEMO.md). Проверены перечисленные
действия и серверные сценарии; это не гарантия отсутствия ошибок при любых
возможных данных и настройках браузера.

## Зависимости и ограничения проверки

```bash
npm audit --omit=dev
npm audit
```

На указанную дату аудит зависимостей приложения показал **0 уязвимостей**.
Полный аудит сообщил о **16 замечаниях moderate** в цепочке инструментов ESLint,
связанных с `minimatch`. Эти зависимости нужны для проверки кода. Принудительная
замена версий через `npm audit fix --force` не применялась.

Число замечаний может меняться при обновлении базы аудита или зависимостей.
Нагрузочное тестирование, антивирусная проверка файлов и работа в облачном
окружении в этот прогон не входили.
