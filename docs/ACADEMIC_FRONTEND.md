# Фильтры и сохранение в браузере

## Реализовано

- Фильтры студенческих заданий по предмету и типу вместе с поиском, статусом и сроком.
- Фильтры расписания с ограничением по аккаунту, сбросом и числом результатов. Переходы день/неделя сохранены.
- Фильтры обзора администратора и преподавателя; показатели соответствуют выбранным занятиям.
- Фильтры заданий и проверки преподавателя, сохранение фильтров журнала, сохранён CSV-экспорт.
- В справочниках — курс группы и предмет преподавателя; в аудиториях — текущая занятость по полному расписанию администратора.
- Общий механизм localStorage, подключённый к интерфейсу. Черновики проверки переживают переход и перезагрузку, удаляются отдельно либо после публикации.
- Сверка устаревшего черновика с новой версией работы. Публикация до явного подтверждения заблокирована.
- Русские, казахские и английские подписи; адаптация фильтров к узкому экрану.

## Как устроено сохранение

`storageKey` формирует ключ вида `studyhub:v1:user:<ID>:<область>:<объект>`.
У двух пользователей разные ключи, даже на одном компьютере. При переключении аккаунта
новое состояние создаётся до отображения, а прежнее отключается.

На сервере и при первой отрисовке используются одинаковые начальные значения.
Хранилище читается только после монтирования в браузере. Автоматической записи начального
состояния нет: запись выполняется сразу при пользовательском изменении после восстановления.
Поэтому закрытие диалога не теряет последний ввод и нет отложенных таймеров другого пользователя.

Каждый потребитель проверяет структуру JSON. Сохранённые ID фильтров дополнительно сверяются
с доступными пользователю данными. Неизвестные значения сбрасываются. Дата расписания в
localStorage не записывается: новое открытие показывает текущую дату школы.

Надпись «Сохранено» появляется только после успешной записи. При ошибке ввод остаётся в памяти,
показывается предупреждение. Сброс фильтров работает в памяти и при запрещённом хранилище.
`localStorage.clear()` не используется. Серверные данные, пароли, токены и права доступа не копируются.
После публикации удаляется запись черновика; остальные черновики сохраняются.

## Что требует изменений коллег

В ветке `feat/academic-rules-api` фильтры и черновики объединены с серверными
учебными правилами. Сохранены фиксированные пары в обычном занятии, выбор
`lessonId` при публикации задания и отображение СРСП без собственного времени
и аудитории. Расписание и обзор используют дату связанной практики.
Серверные требования к настройке базы описаны в [памятке backend](BACKEND-ACADEMIC.md).

Оставшаяся интеграция зависит от согласованных изменений базы данных
(`feat/academic-data`) и компонентов интерфейса (`feat/student-tools-ux`).

Не реализованы и не выдаются за готовые:

- Зависимые списки учебного плана и языков преподавания в формах,
  полная форма создания СРСП с выбором `practiceId`.
- Запрос `/api/rooms/availability`, отмена устаревших ответов и подбор аудитории на пару.
- Размещение СРСП непосредственно рядом с практикой.
- Фильтры по программе/языку группы, языку преподавателя, этажу и типу аудитории.
- Подключение `TaskNotesPanel` и `FavoriteButton`: компонентов коллег пока нет.

В общем хранилище подготовлены валидаторы прогресса и избранного. Они не означают,
что интерфейс заметок и избранного уже подключён.

После получения веток список предметов в форме занятия должен зависеть от учебного плана
группы. Преподаватели должны отбираться по предмету, языку группы и назначениям.
При изменении родительского поля несовместимые значения очищаются; пустой список получает
объяснение. Пары импортируются из backend-модуля `lesson-rules.mjs`, без второго списка интервалов.
Это план оставшейся интеграции; текущие формы используют объединённый API.

## Локальная проверка

Используется отдельная SQLite-база `../studyhub-data/academic-frontend`.
`DATABASE_URL` пуст, рабочая Neon и публикация не менялись.

```sh
npm run dev -- --hostname localhost --port 3010
```

Адрес: http://localhost:3010. Через «Учебный доступ» можно переключать роли.
Для проверки конфликта в этой локальной базе повторно отправлена одна учебная работа
и опубликован результат после явной сверки. Рабочие данные сайта не затрагивались.

Автотесты добавлены для хранилища/SSR, восстановления, ошибок JSON/доступа, разделения
пользователей, фильтров и допустимых значений. Проверки запускаются обычным `npm test` после сборки.

Проверено 10 ноября 2026 года: `npm run lint`, `npm run build` и полный `npm test`
прошли. После исправления защиты нового черновика от позднего ответа повторно прошли
lint, сборка и 18 тестов хранилища/черновиков. Всего добавлены 24 функциональные проверки.
В браузере проверены восстановление после перезагрузки, смена роли, реальная пересдача
и конфликт версий, удаление опубликованного черновика, CSV с выбранным студентом,
фильтры администратора, текущая дата расписания, три языка и мобильная тёмная/светлая тема.
