# Формы, расписание и проверка работ

В длинных списках появился поиск. В форме занятия группу можно отобрать по направлению,
году поступления и языку. Аудиторию — по этажу, типу и доступности для выбранной группы,
даты и пары. Этажи берутся из справочника, поэтому фильтр работает и для здания с 11 этажами.
Выбранное значение не сбрасывается при поиске: оно остаётся в списке с пояснением.
Если сервер ещё не проверил занятость, форма не показывает аудиторию как свободную.

СРСП хранит ссылку на практику. Для отображения даты, времени и аудитории используется
`lessonSchedule()`. В самой записи СРСП время и аудитория остаются пустыми: повторного
бронирования нет. Изменение лекции не перемещает практику. Изменение практики автоматически
меняет отображаемые сведения её СРСП.

«Скрыть занятие» убирает запись из расписания, но сохраняет задания, работы, оценки и файлы.
Практика скрывается вместе со своими СРСП. Оценки остаются в журнале; существующие работы
доступны для проверки и скачивания. Отмена занятия остаётся отдельным действием.
Порядок обновления Neon описан в [LESSON-ARCHIVE.md](LESSON-ARCHIVE.md).

После сохранения оценки в проверке работ доступна кнопка «Посмотреть оценку в журнале».
Она открывает нужные группу, предмет и студента, прокручивает журнал до нужной ячейки
и выделяет её на пять секунд. Кнопка «Назад к проверке работы» возвращает к той же работе.
В ссылке передаются только идентификаторы; права доступа сервер проверяет независимо от ссылки.

В таблицах нажатие на заголовок меняет направление сортировки. Числа сравниваются как числа,
пустые значения остаются в конце, одинаковые значения сохраняют исходный порядок.
В справочниках сначала сортируется весь отфильтрованный список, затем выбирается страница.
Колонка с кнопками действий не сортируется.

Окно диалога ограничивает прокрутку внутренним содержимым. Заголовок и кнопка закрытия
остаются сверху, скруглённая рамка обрезает края полосы прокрутки. Используется нативный
`dialog`: Escape, фокус внутри окна и возврат фокуса к кнопке открытия сохраняются.

## Проверки перед публикацией

Автоматические проверки запускать из корня проекта на Node.js 24:

```powershell
npm ci
npm run lint
npm run build
npm test
node --test tests/lesson-archive-migration.test.mjs tests/lesson-archive-backend.test.mjs tests/lesson-display.test.mjs tests/review-journal.test.mjs tests/table-sort.test.mjs
```

`npm test` создаёт отдельную SQLite-базу и проверяет HTTP API. Новые тесты проверяют
сохранение связанных данных, права и версии при скрытии, освобождение аудитории,
связь практики и СРСП, точную ссылку на оценку и числовую сортировку.
Они не выполняют миграцию в рабочем Neon.

Сценарии для полного повторного прохода после применения всех четырёх частей
(перечень сам по себе не означает, что все проверки выполнены):

1. На широкой странице и экране телефона открыть «Новое занятие». Прокрутить вниз,
   убедиться, что скругления справа сохранены, крестик доступен, фон не прокручивается.
   Пройти поля клавишей Tab, закрыть Escape и проверить возврат фокуса.
2. В группе использовать поиск и фильтры; выбрать группу и затем изменить поисковую строку.
   Выбор должен остаться видимым. Проверить отсутствие результатов и сброс фильтров.
3. Выбрать дату и пару, отфильтровать аудитории по этажу, типу и свободным местам.
   Проверить 11-й этаж на тестовых данных, занятую и маленькую аудитории. При ошибке сети
   должна появиться возможность повторить проверку, без ложной отметки «Свободна».
4. На тестовых занятиях изменить время и кабинет лекции — практика должна остаться прежней.
   Переместить практику — соответствующая СРСП должна показывать новое время и кабинет.
   Сама СРСП не должна бронировать аудиторию повторно.
5. Скрыть тестовую практику с СРСП и выставленными оценками. Обе записи исчезают из расписания;
   оценки, задания, работы и файлы остаются. Проверить журнал под преподавателем и студентом.
6. Выставить работе 0, затем 95. После каждого сохранения перейти в журнал, проверить
   точную ячейку и краткую подсветку. Вернуться назад к той же работе. Проверить поиск
   и сохранённые фильтры очереди работ.
7. В пользователях, группах, предметах, назначениях, аудиториях, журнале, проверке работ
   и оценках студента проверить оба направления сортировки. В пользователях перейти
   на вторую страницу и убедиться, что порядок общий. Проверить 9/100, этажи 2/11,
   пустые оценки и «н.п.».
8. Повторить основные сценарии на русском, казахском и английском, в обеих темах.

## Фактическая браузерная проверка 17 ноября 2026 года

Проверка выполнена автоматизацией интерфейса браузера на `http://127.0.0.1:3184`
с отдельной временной SQLite-базой и тестовыми записями. Рабочая Neon и опубликованный
сайт в ней не использовались. Подтверждены следующие действия:

- Диалог «Новое занятие» проверен в 12 сочетаниях: RU/KK/EN, светлая/тёмная тема,
  экран 1280 × 720 и 390 × 844. Прокручивается тело окна, оболочка обрезает
  содержимое по рамке, крестик остаётся в видимой области, прокрутка фона заблокирована.
- При проходе Tab до нижних кнопок заголовок остался на прежней высоте 37 px.
  Escape закрыл окно и вернул фокус к кнопке добавления занятия.
- Выбранная группа ИС-21 сохранилась при поиске `ZZZZ` и показывалась с пояснением
  о сохранённом выборе. Сброс фильтров расписания очистил выбор и поисковые строки.
  Enter в поиске формы создания пользователя оставил форму открытой, без сохранения.
- Сортировка пользователей по почте работает до пагинации: первая страница
  заканчивалась записью `s0109`, следующая начиналась с `s0110`. Переключение на
  убывание вернуло список на первую страницу.
- В аудиториях этажи шли как 2, 11, пустые и в обратном направлении как 11, 2,
  пустые. Вместимость сортировалась численно, включая 9 и 100. Фильтр 11-го этажа
  оставил одну тестовую аудиторию 1109.
- Практика на 18 ноября перенесена через интерфейс с четвёртой пары на пятую.
  Связанная СРСП показывала 11:50–12:40; лекция осталась на 09:50. Фильтр аудитории
  включал практику и её СРСП. После подтверждённого скрытия практики обе записи
  исчезли из расписания. Сохранность оценок и файлов при скрытии в браузере
  отдельно не проверялась; для неё предусмотрены автоматические тесты.
- Преподаватель сохранил тестовой работе 0, перешёл к подсвеченной ячейке 0 в
  журнале, вернулся к той же работе, сохранил 95 и перешёл к подсвеченной ячейке 95.
- Диалог студента с заголовком из 102 символов без пробелов проверен на ширине
  320 px: горизонтального переполнения нет, крестик виден.
- Исключений приложения в консоли не обнаружено. В консоли присутствовало
  перенаправленное Next.js предупреждение Node.js `ExperimentalWarning` о SQLite.

Эта проверка не охватывает каждый пункт полного сценария. В браузере остаются
непроверенными ошибка сети и повтор проверки доступности аудитории, все таблицы
в обоих направлениях и во всех языках/темах, переводы названий занятий в оценках
студента, сохранность всей истории после скрытия, поиск и восстановление фильтров
очереди работ. Матрица из 12 сочетаний относится к диалогу нового занятия,
а не ко всем действиям приложения.

До просьбы пользователя пропустить оставшиеся тесты успешно выполнены
`npm run lint` и отдельный прогон 27 тестов сортировки, фильтров, переводов,
отображения занятий, формы занятия и перехода из проверки в журнал.
`npm run build` завершился успешно при повторном запуске с предупреждением
о версии Next.js. Полный `npm test` по прямой просьбе пользователя не запускался.

При подготовке исходного пакета PostgreSQL проверялся адаптером SQL; текущая
браузерная проверка использовала SQLite. Перед рабочей миграцией нужна отдельная
проверка на тестовой ветке Neon.

Сборщик установленной версии Next.js 16.4.2 сообщил об известной уязвимости.
Предупреждение появилось и при повторном запуске сборки 17 ноября.
Обновление Next.js и повторная проверка зависимостей нужны отдельной задачей;
четыре пакета сохраняют исходный набор зависимостей проекта.
