StudyHUB — примеры для проверки проекта

Заполнение текущей базы:
1. Установить зависимости: npm install (нужен Node.js 24+).
2. Выполнить npm run demo:seed.
3. Запустить npm run dev -- --hostname 127.0.0.1.
4. Открыть http://127.0.0.1:3000/.

Чтобы добавить расширенный набор к уже заполненной базе:
npm run demo:seed -- --more
Он дополняет прежние группы и добавляет новые группы, предметы,
преподавателей, аудитории, занятия и работы: ещё 60 студентов,
4 преподавателя, 4 группы, 4 предмета, 4 аудитории, 100 занятий,
20 заданий и 80 работ. Также добавляются оценки, посещаемость и материалы.
Основной преподаватель получает новую группу и больше заданий.
Прежние пароли, оценки
и остальные записи не перезаписываются. Для новых аккаунтов создаётся
отдельный файл .studyhub/demo-access-more-*.json.
Каждый из двух наборов загружается только один раз. При повторном запуске
того же набора дубликаты не появляются. Расписание строится с учётом
уже существующих занятий, а перед записью пересечения проверяются ещё раз.

Команда добавляет 2 группы, 3 преподавателей, 12 студентов, 4 предмета,
4 аудитории, 18 занятий, 6 заданий, 11 сданных работ, оценки и посещаемость.
Имена и учебные данные вымышлены. Группы, предметы и аудитории помечены «демо».
В интерфейсе отображается пояснение о демонстрационных записях.

Доступы генерируются отдельно на каждом компьютере. Команда выводит путь
к приватному файлу .studyhub/demo-access-*.json: teacher — основной
преподаватель, student — основной студент, accounts — все тестовые аккаунты.
Пароли не вшиты в код и не показываются на странице входа. Файл с паролями,
база и резервные копии исключены из Git.

Что показать преподавателю:
— В админском аккаунте: обзор текущих занятий, расписание, справочники,
  создание и редактирование занятия, проверка пересечений.
— Под аккаунтом teacher: журнал с оценками, изменение оценки, вкладка
  «Посещаемость», сохранение отметок, «Проверка работ», просмотр SQL/TXT,
  выставление оценки и комментария или возврат на доработку.
— В «Мои задания»: создание задания для назначенной группы и предмета.
— Под аккаунтом student: свои оценки и посещаемость, задания, результат
  проверки, отправка файла на непроверенное задание.
— Обновить страницу: изменения остаются в базе.

Время занятий и сроки выбираются относительно первого запуска команды.
Повторный запуск не сбрасывает изменения и не переносит даты. Для новой
изолированной демонстрации можно задать другой приватный STUDYHUB_DATA_DIR;
существующую базу для обновления примеров удалять не требуется.

Перед добавлением примеров создаётся резервная копия существующей базы
в .studyhub/backups/before-demo-*.sqlite. Заполнение выполняется целиком
в транзакции; конфликт имён или идентификаторов отменяет добавление.
Существующий админский аккаунт и реальные записи не заменяются.
