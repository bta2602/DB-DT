# База данных StudyHUB

Сайт работает с **SQLite**, встроенной в Node.js 24. Это настоящая реляционная
база с таблицами, внешними ключами, индексами и транзакциями. Браузер обращается
к обработчикам Next.js в `app/api/`; прямого доступа к SQLite у браузера нет.

## Где лежат данные

`STUDYHUB_DATA_DIR` задаёт отдельный каталог на компьютере или сервере.
В нём создаётся `auth.sqlite`: несмотря на историческое имя, файл хранит
пользователей, сессии, расписание, задания, оценки, посещаемость, объявления,
материалы и содержимое загруженных файлов. Файлы `.sqlite-wal` и `.sqlite-shm`
служебные; их нельзя удалять при работающем сайте.

Для демонстрации используйте `npm run demo:setup`. Повторный запуск сохраняет
уже введённые оценки, работы и пароли. Добавленные во время демонстрации
аккаунты тоже относятся к демонстрационной базе. Не вводите в неё реальные
персональные данные: в этом режиме доступен вход администратора без пароля.

Обычная база и демонстрационная должны находиться в **разных каталогах**.
Переключение ролей работает только при `STUDYHUB_DEMO_MODE=true`, явном
`STUDYHUB_DATA_DIR` и отсутствии обычных аккаунтов в этой базе. Для настоящих
пользователей выключите деморежим, выберите другой каталог и создайте
администратора через `npm run admin:create`.

## Исходники

- `schema.mjs` — SQL, который выполняет сервер: таблицы и индексы SQLite.
  SQL экспортируется строками, поэтому Next.js включает схему в сборку.
- `seeds/demo-data.mjs` — вымышленные пользователи и учебные примеры.
- `seeds/demo-more-data.mjs` — дополнительный набор для большой демонстрации.
- `../scripts/seed-demo.mjs` — запись примеров в базу, резервная копия перед
  заполнением и случайные пароли в приватном каталоге данных.
- `../lib/studyhub/auth-store.mjs` — подключение, совместимые изменения
  существующей схемы, аккаунты, сессии, справочники и расписание.
- `../lib/studyhub/learning-store.mjs` — задания, оценки, работы и материалы.
- `design/postgresql.sql` — сохранённый первоначальный проект PostgreSQL от
  участника команды. Он не выполняется приложением и не является миграцией SQLite.

Учебные строки из `seeds/` используются только командой заполнения. Интерфейс
получает данные из базы, а не импортирует эти файлы. Пароли хешируются с `scrypt`,
операции записи проверяют роль, CSRF-токен и версию изменяемой записи.

Для запросов по студенту, преподавателю и группе настроены индексы. SQLite
работает в режиме WAL; работы и оценки отбираются SQL-запросом для текущей роли.
Файлы базы, резервные копии, пароли и `.env.local` не должны попадать в Git.
