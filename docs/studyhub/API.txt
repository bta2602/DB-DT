StudyHUB — серверная интеграция (bta2602)

Исходники этой части:
lib/studyhub/api-contract.ts — типы DTO, маршруты и ограничения загрузок.
lib/studyhub/policy.mjs — функции прав доступа и проверки значений.

Это контракт и правила для реализации сервера. Здесь нет HTTP-обработчиков,
проверки паролей, серверных сессий и подключённой БД.
Полноценный сервер команда подключает отдельно.

ПОДКЛЮЧЕНИЕ FRONTEND

Frontend расположен в public/studyhub/ и обращается к /api/*
того же origin.

GET /api/session возвращает:
{ user: null | User, csrfToken: string }

Роль определяется проверенной серверной сессией.
Роль из URL или тела запроса не назначается.

GET /api/bootstrap возвращает все массивы типа Bootstrap,
в том числе пустые массивы, если данных пока нет.

Каждый запрос проверяет сессию, роль пользователя и назначение
преподавателя группе и предмету.

Ограничения доступа применяются на сервере.
Полная БД клиенту не передаётся.

СЕССИИ И ОТВЕТЫ

Серверные сессии хранить в HttpOnly-cookie.
Для HTTPS использовать Secure.

Проверять Origin и CSRF.
Frontend отправляет X-CSRF-Token при изменениях.

Пароли, ключи, токены и .env с секретами в Git не добавлять.
В DTO пользователей не включать хеши паролей или данные сессий.

Успешные изменения возвращают:
{ "ok": true }

После успешной записи UI перечитывает /api/bootstrap.

Ошибки возвращаются в формате:
{
  "error": {
    "code": "ERROR_CODE",
    "message": "Сообщение пользователю",
    "fields": {
      "fieldName": "Ошибка поля"
    }
  }
}

fields — необязательное поле.

HTTP-статусы:
401 — требуется вход;
403 — недостаточно прав;
409 — конфликт версии или расписания;
422 — некорректные данные;
5xx — ошибка сервера.

ВЕРСИИ И СОХРАНЕНИЕ

Версии записей обязательны.
При конфликте вернуть 409 без перезаписывания чужих изменений.

Проверку версии и изменение записи выполнять атомарно в БД.

Снятая оценка остаётся в Bootstrap как grade: null
с актуальной version.

version: null в запросе оценки означает,
что записи оценки ещё не было.

Посещаемость сохраняется одной транзакцией
по lesson.attendanceVersion.

Оценка и обратная связь относятся к конкретной сдаче,
а не ко всему заданию.

ЗАГРУЗКА РАБОТ

Максимальный размер файла: 20 МБ.

Разрешённые расширения:
PDF, DOCX, ZIP, SQL, TXT, PNG, JPG, JPEG.

Размер, формат, содержимое и права проверяются на сервере.

Файлы хранить вне public/ под непредсказуемыми ключами.

GET /api/files/:id каждый раз проверяет доступ.

При повторной сдаче создавать новый fileId,
чтобы клиент не получил старую версию файла.

РАСПИСАНИЕ И СПРАВОЧНИКИ

Дата и время передаются в ISO-формате с часовым поясом.
UI отображает время в Asia/Qyzylorda.

Пересечения группы, преподавателя и аудитории проверяются
на сервере и в БД, включая одновременные запросы.

Допустимый курс группы: от 1 до 6.

Администратор создаёт учётные записи без передачи паролей
через текущий UI.

За выдачу доступа и восстановление пароля отвечает
отдельный серверный процесс.
