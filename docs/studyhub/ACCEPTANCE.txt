StudyHUB — приёмка UI (didarochKA)

Общая палитра: public/studyhub/tokens.css.
Оформление компонентов: styles.css, teacher.css, admin.css, publication.css.

До подключения API проверить:
1. На /studyhub/index.html открывается форма входа без тестовых аккаунтов и ролей.
2. Ошибка входа не открывает кабинет и не показывает успешное сохранение.
3. Данные из старого прототипа не подставляются; в пустой БД корректные пустые состояния.
4. На ширине 390px страница не имеет горизонтального переполнения; таблицы
   прокручиваются внутри своего контейнера. Видны кнопки, подписи и фокус.
5. Формы доступны с клавиатуры; модальное окно возвращает фокус при закрытии.

После подключения настоящего API дополнительно проверить:
6. Гость не получает учебные данные. URL/hash не создаёт роль или сессию.
7. Студент видит свою группу, сдачи, оценки и посещаемость.
8. Преподаватель видит только назначенные предметы/группы.
9. Сдача -> доработка -> пересдача -> оценка работает в разных сессиях.
10. Загруженный файл остаётся доступен после перезагрузки с проверкой прав.
11. Массовая посещаемость не перезаписывает индивидуальные отметки.
12. Ошибка сети сохраняет черновик, не подтверждает неудачную запись.
13. Параллельное изменение возвращает 409; чужие изменения не теряются.
14. Расписание отклоняет пересечения группы, аудитории и преподавателя.
15. Выход закрывает серверную сессию; повторный вход работает.

Автоматические проверки из корня после объединения четырёх частей:
node --test tests/frontend/api.test.mjs tests/frontend/logic.test.mjs tests/backend/policy.test.mjs tests/ui/publication.test.cjs

Автотесты правил и UI-контракта не заменяют приёмку реального backend и БД.
